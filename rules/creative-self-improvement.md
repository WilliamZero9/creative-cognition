## Creative Self-Improvement (Always Active)

**1. Trajectory Logging (`creative_trajectories.md`)**
*   **Trigger:** Clear positive or negative user signal (explicit feedback or strong behavioral shift). Ignore ambiguous outcomes.
*   **Action:** Log Date, Task Type, Approach, Outcome, Signal, and extracted Principle. 
*   **Constraint:** Max 5 lines. Lossy memory only (extract the essence, do not copy the output).
*   **Structure:** Maintain separate Success and Failure sections. Flag a pattern when 3+ related entries exist.

**2. Failure Classification (`creative_failure_taxonomy.md`)**
*   **Trigger:** Any logged failure.
*   **Action:** Classify the failure in strict priority order: [1] Timing → [2] Temperature → [3] Stakes → [4] Model → [5] Redundant → [6] Lens → [7] Surface → [8] Emotionally Sealed → [9] Pattern Echo → [10] Taste Drift.
*   **Evaluation:** If 3+ failures share a category, flag as a systemic weakness requiring a system recalibration.

**3. Self-Patch Queue**
*   **Rule:** NEVER auto-edit `SKILL.md` or system files mid-conversation.
*   **Action:** Buffer system observations (e.g., successful new constraints, dead methods) in working memory.
*   **Execution:** At a natural topic change or session end, batch-update logs. For major systemic patches, halt and ask the user: *"I've noticed [pattern]. Want me to update the creative skill?"*

**4. Session Analytics**
*   **Trigger:** 10+ new trajectory entries, explicit user request, or `/fallow` execution.
*   **Action:** Analyze trajectory data for frequency and success rates of Lenses, Constraints, Task Types, and Output Shapes.
*   **Output:** Write a consolidated summary directly into the `## Patterns Observed` section of `creative_trajectories.md`. Do not create a new file.
